# 产品规划：室内机 → 智能家居中控台

> 定位一句话：**一块 320×480 的带屏室内机，长成智能家居中控台的样子 —— 手能点、嘴能说、门铃能响、视频能看。**
> 目标平台 RK3308（4×A35、无 GPU、RGB 屏），本机先用 SDL 模拟器把全部业务逻辑做完，板子到位只换 HAL。
> 对应岗位：深渡科技 RK3308 语音中控（LVGL 界面/动画/内存优化 + 思必驰语音 + 整机稳定 + SIP 对接门口机）。

---

## 1. 整体架构

```
┌────────────────────────────────────────────────────────────────┐
│                        src/ui/  界面层（纯 LVGL）                │
│  ui_home        中控主页（房间页签 + 设备九宫格 + 场景卡）        │
│  ui_voice       语音浮层（唤醒光环 / 识别结果 / 执行反馈）        │
│  ui_call        对讲页（来电横幅 / 通话中 / 视频区 / 挂断）       │
│  ui_settings    设置页（设备管理 / 主题 / 关于）                  │
│  ui_theme       命名样式 + 明暗主题（已有）                       │
├────────────────────────────────────────────────────────────────┤
│                     src/app/  应用层（平台无关）                  │
│  app_devices    设备模型：房间/设备/状态/持久化                   │
│  app_voice      语音链路：唤醒态 → ASR 文本 → 意图解析 → 执行     │
│  app_sip        对讲链路：注册/来电/通话状态机（SPI 接协议栈）     │
│  app_events     事件总线：各模块解耦，UI 只订事件不碰逻辑          │
│  app_stats      FPS/内存/循环耗时埋点（已有）                     │
│  app_mock       设备/语音/来电模拟源（已有，无板联调的命根子）     │
├────────────────────────────────────────────────────────────────┤
│                     src/hal/  平台抽象（唯一换板接口）            │
│  hal_sdl.c      Win/Linux 桌面（已有）                           │
│  hal_fbdev.c    RK3308：/dev/fb0 + evdev 触摸（P1 待写）         │
│  hal_audio.c    音频抽象：PC=SDL audio / 板=ALSA+硬件codec（P1）  │
├────────────────────────────────────────────────────────────────┤
│  板级依赖（用户态库，都在 app 层后面换）                          │
│  思必驰 SDK（唤醒+离线ASR）· 在线语音SDK（云端ASR）· oSIP/eXosip（SIP）│
│  ·  设备侧协议 MQTT/RS485（中控→执行器）                         │
└────────────────────────────────────────────────────────────────┘
```

三条硬规矩（工程纪律，面试能讲）：

1. **UI 不认识业务**：`ui_*` 只消费 `app_events` 里的状态、只发动作请求，设备是灯还是插座 UI 不关心；
2. **协议栈不认识 UI**：`app_sip` 面向"呼叫状态机"编程，oSIP/eXosip/思必驰都是可替换实现；
3. **一切可模拟**：每个外部依赖（语音、来电、设备、音频）都有 mock 通道，`LVGL_MOCK=1` 全链路无板可跑。

## 2. 功能点拆解

### 2.1 智能家居中控台 UI

**页面结构**（P0-2/P0-3 的落地对象，flex/grid + 页面栈在这里练）：

| 页面 | 内容 | 交互 |
|---|---|---|
| 主页（中控台） | 顶部状态栏：时间/天气/SIP 在线/语音待唤醒指示；房间页签（客厅/卧室/全宅）；设备九宫格（灯/窗帘/空调/新风口/摄像头/插座）；底部场景条（回家/离家/睡眠/观影） | 点设备开收起动画；长按进详情（亮度/色温/风量滑条） |
| 语音浮层 | 唤醒后全屏变暗 + 麦克风光环动画 + 实时识别文本 + 执行结果图标 | 3s 无操作/执行完成自动收起 |
| 对讲页 | 来电：横幅（门口机号+头像）+ 接听/拒收；通话中：视频区 + 挂断/开锁/静音 + 通话时长 | SIP 状态机驱动 |
| 设置页 | 主题切换（已有）、设备管理、音量、关于（版本/内存信息页） | |

**中控台风格要点**：设备卡片要能表达状态（开=亮色+图标点亮、关=暗色），状态切换带 200ms 过渡动画 —— 这就是 JD 里"动画"的落点；所有坐标用 flex/grid，不做绝对定位。

### 2.2 语音唤醒 + 指令理解（主路径：思必驰 / 在线语音 SDK）

> 定调依据：JD 明确写 **"有思必驰/在线语音 SDK 调试经验优先"** —— 所以语音方案不发明轮子，
> **唤醒和识别全部交给 SDK，应用层做的是"SDK 的正确用法 + 与中控台的业务接线"**。
> 规划按 SDK 的真实调试形态来写，本机阶段用同构接口 mock，上板直接换 SDK 实现。

**SDK 双轨 + 免费过渡**（JD 给的两条路都接住，接口统一）：

| 后端 | 何时用 | 能力 | 费用 |
|---|---|---|---|
| **sherpa-onnx 本地引擎**（★现阶段真调） | 本机现在就用，板子也能跑 | 开源（Apache/MIT）：关键词唤醒（中文，模型仅 3.3M）+ 流式 ASR（zipformer 中英 ~80MB）+ 离线 TTS + VAD，C/C++ API，Win/Linux/ARM 全平台，**100% 离线** | 免费 |
| **思必驰离线 SDK**（板上量产主路径） | 拿到板子/SDK 后 | 唤醒词引擎 + 离线命令词/ASR + VAD，厂商调优，断网可用 | 商务授权 |
| **在线语音 SDK**（云端补充，可选） | 网络可用且要自由说法 | WebSocket/HTTP 流式识别，词库无限制 | 按量 |
| **mock 引擎**（CI/演示） | 自动化测试、无麦克风环境 | 文本注入，模拟 SDK 的全部回调时序 | 免费 |

> **为什么是 sherpa-onnx**：思必驰 SDK 有商务门槛、板子没到之前碰不到；sherpa-onnx 免费开源、
> 模型走 ModelScope 国内下载很快、C/C++ API 直接链进本工程，**唤醒+识别+TTS 全离线零云依赖**，
> 且 RK3308 这类 ARM 板完全跑得动（KWS 模型 3.3M，A35 实时无压力）。
> **"写两套代码"的练法**：先用 sherpa-onnx 把 voice_engine 接口真调通（真实麦克风、真实唤醒、真实识别），
> 板子到位换思必驰实现 —— 接口一行不改，两套引擎对比着调，这本身就是"SDK 调试经验"最硬的素材。

四个后端实现**同一个接口**（`app_voice.h`），UI 和设备层完全不感知差异：

```c
/* voice_engine_t：sherpa-onnx / 思必驰 / 在线语音 / mock 四个实现共用 */
int  voice_engine_init(const voice_cfg_t *cfg);      /* 采样率/唤醒词/命令词表 */
int  voice_engine_start(void);                        /* 进 IDLE，开始喂 PCM */
void voice_engine_feed(const int16_t *pcm, int n);    /* 音频线程喂 PCM（16k/16bit/mono） */
/* SDK 回调（在 SDK 线程触发，应用层只投事件队列）： */
/*  on_wakeup()                  → UI 起光环动画，进 LISTENING */
/*  on_asr_text(text, is_final)  → UI 实时字幕 */
/*  on_result(intents[], n)      → 交设备层执行 */
```

**链路**（按思必驰的典型数据流写，P1 实装时照此对接）：

```
麦克风阵列/codec → [PCM 16k/16bit] → [唤醒词检测] → [VAD + ASR] → [意图解析] → [设备执行] → [UI反馈 + TTS播报]
  hal_audio(P1)      voice_engine_feed   sherpa-onnx    sherpa-onnx/思必驰   app_voice       app_devices   hal_audio
  (板:ALSA)          (PC:SDL录音)        (现在就能真调)  (板上换思必驰)      （★本机就做完）  （★本机就做完） （P1）
```

**意图解析层**（本机自写，上板双轨）：思必驰支持命令词/BNF 语法直接出结构化结果，本机先用自研解析器跑通业务，接口对齐"文本→意图数组"，上板后哪边好用走哪边：

- 语法：`[动作] [设备] [房间?] [参数?]`：
  - `打开客厅的灯` → `{action=ON, device=light, room=living}`
  - `把空调调到 26 度` → `{action=SET, device=ac, param={temp:26}}`
  - `全部关掉` / `打开窗帘然后关灯`（顺序两条）
- 唤醒状态机：`IDLE → LISTENING(光环动画) → PARSING → EXECUTING(设备动画) → FEEDBACK(TTS) → IDLE`，每步超时回 IDLE；
- 免唤醒指令：对讲来电时 `接听/挂断/开锁` 语音直达（真实产品细节）。

**思必驰 SDK 调试经验补课清单**（把"经验优先"变成真有得聊，面试前过一遍）：

1. 授权/license：SDK 通常按设备绑定授权，首次启动失败先查 license 文件与机器码；
2. 音频格式匹配：唤醒引擎一般要 16k/16bit/单声道定点 PCM，采样率/位宽/声道不对是最常见的"识别不了"；
3. 线程模型：SDK 回调在**自己的线程**里 —— 回调里禁止直接碰 LVGL 对象，必须投事件队列（本工程的并发纪律正好对上）；
4. 命令词/语法资源：命令词表（拼音/BNF）编译与热更新；
5. 唤醒调优：唤醒灵敏度 vs 误唤醒率，VAD 起止点参数；
6. 排障手段：SDK 日志级别、pcm 回灌保存分析、cpu 占用（A35 上语音 SDK + LVGL 同跑的内存/算力预算）。

**本机两条路**：

1. **真麦克风（sherpa-onnx）**：SDL2 录音（16k/16bit/mono，已有依赖）→ KWS 唤醒（模型 3.3M，走 ModelScope 下载）→ 流式 ASR（zipformer 中英 ~80MB）→ 意图 → 执行。**全离线，零云依赖，现在就能对着电脑喊"小爱同学"式唤醒词**；
2. **mock 注入（CI/演示兜底）**：mock 引擎按 SDK 时序发回调（`app_mock` 已有 9s 一条假 ASR，扩展中文短语表 + `LVGL_VOICE_CMD="打开客厅的灯"` 手动注入，演示可当输入框用）。

### 2.3 SIP 音视频对讲

这是你的王牌（大华 VTH 五年 + oSIP/GB28181 迁移经验），demo 里做成第一公民：

**网元与流程**：室内机（VTH）←SIP→ 门口机（VTO）/ 手机 APP，注册到室内机本体或小 PBX；呼叫信令 INVITE/180/200/ACK/BYE，媒体 RTP。

**呼叫状态机**（`app_sip`，协议无关）：

```
IDLE → INCOMING(横幅+铃声) → ANSWERED(视频区起播+计时) → BYE → IDLE
         │ 拒接/超时             │ 挂断
         └──────────────────────┴→ IDLE
另有：注册状态 OFFLINE/ONLINE（状态栏指示）、断线重连、免打扰(DND)。
```

**音视频通路分两档**：

- 桌面模拟：视频区放占位动画/静态帧 + 音频 mock（SDL 播铃声）；
- 板子：SIP 信令用 oSIP/eXosip（自带媒体，或 RTP 收流送硬件解码），音频走 `hal_audio`（ALSA + RK3308 codec），视频 H264 硬解 → 直接往 LVGL 的 canvas/image 控件灌 YUV 转 RGB 帧。

**与中控台的联动**（真实产品感）：来电时若正在操作设备，横幅不打断、静音音乐；通话中点"开锁"发 DTMF/私有信令给门口机 —— 这段话术直接对应大华 VTH 的实际行为。

## 3. 数据模型与持久化

```c
/* app_devices.h —— 设备模型（控件化状态机的根基） */
typedef struct {
    const char *id, *name;
    uint8_t room;              /* 房间枚举 */
    uint8_t type;              /* light/curtain/ac/... */
    device_state_t state;      /* on/off + type 专有参数（亮度/温度/百分比） */
    uint32_t flags;            /* 在线/故障 */
} device_t;

/* 设备动作统一入口：UI、语音、场景、SIP(开锁) 全走这一个函数 */
int  device_execute(const device_cmd_t *cmd);   /* 异步，完成发 EV_DEVICE_CHANGED */
```

- **事件总线** `app_events`：`publish/subscribe`，最简实现 = 固定数组回调表 + LVGL timer 分发（**UI 线程外只投队列，LVGL 对象只在主线程动** —— 并发纪律，面试必讲）；
- **持久化**：本机 CSV/JSON 文件；板子上 SQLite（协能弹药复用）—— 记住设备状态，断电重启恢复；
- **场景** = 预置命令序列（`{"回家": [ON light.living, OFF alarm, ...]}`）。

## 7. 风险与降级
