# 室内机交付形态 与 SIP 注册设计

> 目标形态：**一个可执行文件、一条 systemd 服务、一份配置文件**。上电即注册上线，
> 现场不需要命令行、不需要环境变量、不需要人盯着。

---

## 0 一句话结论

```
上电 → systemd 拉起进程 → 读 /etc/indoor/sip.ini → REGISTER（401 挑战）→ 200 OK
     → 在线 → 到期前随机时刻续期 → 失败则指数退避重试 → 网络恢复自动回到在线
```

配置走文件，状态写可写分区，行为靠状态机兜底。**没有"人工介入"这个环节。**

---

## 1 交付形态：一个进程，四个线程

室内机不是"一堆程序"，是**一个二进制**里跑四类工作。合并成一个进程的理由是：
共享同一份配置和同一套事件总线，避免跨进程通信和状态同步；代价是内部必须把
实时性差异大的工作**拆线程**——这是硬约束，不是洁癖。

| 线程 | 职责 | 周期 | 实时性要求 |
|---|---|---|---|
| **SIP** | `select` 等 SIP + RTP socket、事务状态机、注册续期 | 事件驱动 + 100ms tick（通话中 20ms） | 中 |
| **声卡** | 每 20ms 从环形缓冲取 160 样本播放 / 录 160 样本入缓冲 | **20ms 硬实时** | 高 |
| **视频**（M3 剩余） | RTP 解包（FU-A/STAP-A）→ 解码 → 双缓冲 | 帧驱动，丢旧不丢新 | 中 |
| **UI 主线程** | `lv_timer_handler()` | 33ms | 低，但**只能在这碰 LVGL** |

不合并的三个理由：

- 声卡回调晚 20ms 就是爆音（欠载），而 UI 一次 flush 在低端板子上可能几十毫秒；
- 解码 480p 一帧 8~12ms，放 UI 线程就是肉眼可见的卡顿，放 SIP 线程会拖垮事务超时；
- **LVGL 非线程安全**，其他线程只能投事件（`app_events`），不能直接碰控件。

### systemd unit（建议）

```ini
[Unit]
Description=DeepSmart Indoor Unit
After=network-online.target sound.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/deepsmart-indoor
Restart=always
RestartSec=2
WatchdogSec=30
# 配置在只读分区，状态在可写分区 —— 两件事必须分开
Environment=INDOOR_CONF=/etc/indoor/sip.ini
WorkingDirectory=/var/lib/indoor

[Install]
WantedBy=multi-user.target
```

**`/etc` 只读、`/var/lib` 可写** 是嵌入式的基本纪律：

| 数据 | 位置 | 丢失后果 |
|---|---|---|
| SIP 账号 / 服务器 | `/etc/indoor/sip.ini`（只读，出厂烧写） | 致命，设备变砖 |
| 设备状态（开关/亮度） | `/var/lib/indoor/devices.ini`（可写） | 无所谓，回默认值 |
| 日志 | journald + 本地轮转 | 无所谓 |

> 现在的 `devices.ini` 是落在工作目录的，上板时由 `WorkingDirectory` 决定位置，
> 逻辑不用改 —— 但要在文档里写死，否则售后会找不到状态文件。

## 2 配置从哪来：三层覆盖

```
编译默认值  →  sip.ini  →  环境变量
（代码里）     （现场）      （调试/CI）
```

优先级**环境变量最高**，这是刻意的：现场要稳定，所以以文件为准；测试要灵活，
所以允许一行命令覆盖任何字段，不必改文件。

### 查找顺序（`app_sip_init_from_env()`）

| 顺序 | 路径 | 场景 |
|---|---|---|
| 1 | `$SIP_INI` 指定 | CI / 多实例测试 |
| 2 | `/etc/indoor/sip.ini` | **产品（板子）** |
| 3 | `./sip.ini` | 开发机（`bin/` 目录） |

代码位置：`src/app/app_sip.c` → `cfg_load_ini()` / `app_sip_init_from_env()`。

一个实现细节值得记住：**配置字符串必须落在静态缓冲里**。`getenv()` 的返回值
生命周期不由我们控制，`fgets()` 的行缓冲下一轮就被覆盖 —— 直接存指针，
现场表现是"跑十几分钟后 SIP 账号变成乱码"。

### 字段表（`config/sip.ini.example`）

| 键 | 默认 | 说明 | 常见错法 |
|---|---|---|---|
| `server` | 无（不填=关闭 SIP） | 服务器/IPPBX 地址 | 填了域名但板子没 DNS |
| `port` | 5060 | 服务器 UDP 端口 | 与 `local_port` 搞混 |
| `user` | 1001 | 本机账号（From / Request-URI） | 填成显示名 |
| `password` | 空 | 认证密码，401 时算 Digest | 带引号、带尾随空格 |
| `expires` | 3600 | 注册有效期（秒） | **现场建议 120~300**，见 §6 |
| `local_port` | 5062 | 本机监听端口 | 与服务器同机时撞 5060 |
| `local_ip` | 空=自动探测 | 本机媒体地址 | **双网卡板子必填**，否则 SDP 里 `c=` 挑错网卡 |
| `no_register` | 0 | 1 = 点对点模式，不需要服务器 | 调试门口机直连时用 |

解析器支持 `#` / `;` 注释（含行内注释，要求注释符前有空白）、`[section]` 忽略、
未知键忽略（向前兼容）。**刻意不引第三方 ini 库** —— 语法就这几行，
多一个依赖不如多 40 行代码可控。

## 3 注册状态机

```
                 ┌──────────── 配置缺失 ────────────┐
                 │                                  ▼
   IDLE ──send_register──► REGISTERING ──200──► ONLINE ──50~80% expires──┐
     ▲                        │   ▲                 │                    │
     │                        │   │                 │ 续期               │
     │                     401│   │200              └────────────────────┘
     │                        ▼   │                 │
     │                  (带 Authorization 重发)      │ 403/404/401×2
     │                        │                     ▼
     │                    32s 超时 / 5xx ──────► ERROR（fatal，停手等人工）
     │                        │
     └──── 退避 1,2,4,...,60s ─┘（网络恢复自动回到 REGISTERING）
```

| 状态 | 含义 | 界面表现 |
|---|---|---|
| `SIP_IDLE` | 未开始 | 灰点"未配置" |
| `SIP_REGISTERING` | 注册中 / 重试中 | 黄点"注册中…" |
| `SIP_ONLINE` | 已注册，可被呼叫 | 绿点"在线" |
| `SIP_ERROR` | 账号类错误，已停止重试 | 红点 + 错误码 |

`ERROR` 与"重试中"必须区分开：前者要人去改配置（密码错、号码没开通），
后者等网络自己好。两者的售后动作完全不同，界面混在一起就会被投诉"一直转圈"。

### 呼叫状态不能污染注册状态

同一个 `s_state` 里既有注册态又有通话态（`RINGING/INCOMING/INCALL`），
所以**任何注册状态更新都要先判断当前是否在通话**：

```c
if (s_state != SIP_INCALL && s_state != SIP_INCOMING && s_state != SIP_RINGING)
    set_state(SIP_ONLINE);
```

漏掉这层的经典现象：通话中出现一次续期，界面从"通话中"跳回"在线"，
按钮也跟着变回"呼叫"。

## 4 失败分类：哪些该重试，哪些该停手

| 响应 | 含义 | 处理 | 现场根因 |
|---|---|---|---|
| 401（第一次） | 正常挑战 | 带 `Authorization` 重发 | —— |
| **401（第二次）** | 密码错 / 摘要算法不匹配 | **fatal，停止** | 密码错、realm 不对、MD5 与 MD5-sess 混用 |
| **403 Forbidden** | 服务器拒绝 | **fatal，停止** | IP 白名单、号码未开通、并发数超限 |
| **404 Not Found** | 域 / 账号不存在 | **fatal，停止** | 服务器地址填错、账号没建 |
| 400 / 405 | 报文或方法不接受 | **fatal，停止** | 服务器只收 TCP，我们发 UDP |
| 408 / 480 / 5xx | 服务器临时问题 | 退避重试 | 服务器重启、过载 |
| **无响应 32 秒** | 丢包 / 网络断 / 地址错 | 退避重试 | 网线没插、VLAN 隔离、防火墙 |
| 连续失败 | —— | 退避 1→2→4→…→**60 秒封顶** | —— |

两条设计原则：

1. **密码错不要自旋。** 每 2 秒重试一次，很多 IPPBX 会把账号锁掉，故障从
   "一个人打不了"升级成"全网这个账号被锁"。停手 + 界面报错，人改完配置重启即可。
2. **退避要有上限。** 600 台设备同时断网恢复，若都按 1 秒重试，服务器会被
   自己的终端打挂。上限 60s + 续期随机化，能把重连风暴摊平。

## 5 事务区分：REGISTER 和 INVITE 共用 CSeq 计数器

响应报文里**只有 CSeq 能说明它属于哪个事务**。不比对 CSeq 的后果很具体：

> 续期窗口内正好有个呼叫被 486 Busy 拒了 → 这条 486 被当成"注册失败" →
> 设备状态从"在线"跳到"注册中" → 界面闪一下，日志里还留着"注册失败(486)"。

所以收到响应先问一句"这是注册事务的吗"：

```c
static bool is_reg_response(osip_message_t *msg)
{
    if (!s_reg_pending) return false;
    if (!msg->cseq || !msg->cseq->number) return true;   /* 对端没回 CSeq：按注册处理 */
    return atoi(msg->cseq->number) == s_reg_cseq;
}
```

## 6 续期与掉线检测

| 项 | 现在 | 为什么 |
|---|---|---|
| 续期触发点 | `Expires` 的 **50%~80% 每个周期现随机** | 固定 50% 会让整批设备同一秒续期，服务器上出现周期性尖峰 |
| `Expires` | 文件可配，默认 3600 | **现场建议 120~300** |
| 掉线发现 | 靠续期失败 | 最坏 = 续期周期 |

`expires=3600` 在实验室很舒服（日志干净），在现场是陷阱：**掉线最坏要 30 分钟
才发现**，客户已经投诉了三轮。`expires=180` 时最坏 1~2 分钟，代价只是每 1~2 分钟
一个几十字节的 REGISTER 包。

想更快（秒级）就加 OPTIONS 保活：每 30s 发一个 `OPTIONS`，3 次不回判掉线。
成本很低，但要注意有些服务器不实现 OPTIONS —— 收到 405 也要当作"链路正常"。
**这一条列在待办里，M6 之前完成。**

## 7 首次配置：现场怎么把账号灌进去

| 方案 | 成本 | 适用 | 风险 |
|---|---|---|---|
| **A 出厂预置** | 最低 | 批量交付（客户是地产/物业，一次几百台） | 装错机器要返工；密码随固件流出 |
| **B 界面配置** | 中（一个设置页） | 售后换机、客户自改 | 要防止误触清空 |
| **C 二维码 / 自动发现** | 高 | 项目型、每户不同 | DHCP Option / mDNS 依赖客户网络策略 |

**建议 A + B**：出厂按序列号批量生成 `sip.ini`（生产工具里一张表），
同时保留一个隐藏设置页改服务器/账号，改完写回 `/etc/indoor/sip.ini`（需可写，
或者写 `/var/lib/indoor/sip.ini` 并让它优先于 `/etc`）。

> 生产工具的思路：Excel 里一列 MAC / 一列分机号 → 批量生成 ini → 打包进
> 单机镜像。不要指望产线工人手输密码。

## 8 密码与安全：先说清楚现状

**当前是明文 ini。** 这在嵌入式对讲行业是常态，但要知道它的边界：

| 措施 | 状态 | 说明 |
|---|---|---|
| 文件权限 `600`、属主为设备用户 | 必须做 | 挡住同机其他进程和售后随手 `cat` |
| 不进 git（`.gitignore` 已排除 `sip.ini`） | 已做 | 只提交 `config/sip.ini.example` |
| 出厂一机一密 | 建议 | 否则一台设备的密码泄露 = 全网可冒充 |
| 加密存储（AES + 设备唯一密钥） | 可选 | 提升的是"拆机读 flash"的成本，不是"防内鬼" |
| TLS（SIPS 5061） | 跨公网必做 | 局域网内收益低、证书运维成本高，客户也不会批 |

**别做"密码写死在代码里"**：改密码要重新发固件，售后会绕过你直接改二进制。

## 9 网络：三种部署形态

| 形态 | 配置 | 注意 |
|---|---|---|
| **小区局域网**（主形态） | `server=物业机房IP` | 一台 IPPBX 带几百户，`expires` 别设太小 |
| **门口机 ↔ 室内机直连** | `no_register=1` | 无平台也能用，SDP 里必须是本机真实网卡 IP |
| **跨公网 / 云平台** | 需要 `outbound proxy` + NAT 穿透 | 必须 TLS + 短 expires；还要处理对称 RTP（已实现） |

两个现场细节：

- **双网卡**（eth0 接小区网、wlan0 备用）：`local_ip` 必须写死，否则 SDP 的 `c=`
  行可能给出 wlan 地址，对端把音频发到不通的网络 → **双方静音，信令全对**。
- **没有 RTC 的板子**：启动时间可能是 1970。Digest 认证不依赖时间（不踩坑），
  但日志时间错乱、证书校验必然失败。开机等 NTP 同步，或先从服务器 `Date` 头取值。

## 10 和服务器侧必须对齐的清单

交付前拿这张表跟运维/集成商逐条确认，能省掉 80% 的现场返工：

| 项 | 要问什么 | 不对齐的后果 |
|---|---|---|
| 地址与端口 | IP:port，UDP 还是 TCP | 400/405，或石沉大海 |
| 域（realm） | 是不是 IP，还是域名 | 401 永远过不去 |
| 账号格式 | `1001` 还是 `1001@domain` | 404 Not Found |
| 认证用户名与号码是否相同 | 有些 IPPBX 两者不同 | 401 循环 |
| 编码 | PCMA / PCMU / 是否强制 Opus | 协商成 Opus → 双方静音 |
| DTMF | RFC2833 还是 SIP INFO | 按键无反应，菜单打不通 |
| 呼叫权限 | 室内机能否直呼另一台室内机 | 403 |
| 最大并发 | 单账号几路 | 第二路被拒 |
| 心跳要求 | 服务器有没有"注册超时踢人" | 30 秒后被踢，表现为"能打进来但一会儿就掉" |
| NAT 方式 | 服务器在公网还是内网 | 单向语音 |

## 12 怎么复现

```bash
# 终端 1：起板端应答器（纯 C，不用 Python）
./bin/sip_echo.exe

# 终端 2：写好 bin/sip.ini（见 config/sip.ini.example），然后什么都不用设
./bin/main.exe

# 预期
[sip] ini sip.ini: 7 项
[sip] cfg: 127.0.0.1:5090 user=echo local=5062 expires=3600
[sip] >> REGISTER sip:echo@127.0.0.1 SIP/2.0
[sip] << 200 OK
[sip] registered (expires=3600)
```

**注意这一行不是环境变量**：`SIP_SERVER` / `SIP_USER` / `SIP_PASS` 一个都没设，
全靠 `sip.ini`。这就是"上电即用"的验证方式。
