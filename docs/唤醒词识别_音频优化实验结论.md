# 唤醒词识别 · 音频优化实验结论

日期：2026-10-28
目标：验证「把输入音频优化成和测试样本一样的节奏、一样的音质」能否提升唤醒识别率。

---

## 一、一句话结论

**不能。这条路已经在四个维度上被证伪。**

同一段 40 秒录音、12 句「你好兮兮」、同一套模型：

| 处理方式 | 意图 | 唤醒召回 |
|---|---|---|
| 原声（基线） | 不改动 | **67%** |
| 匀速压缩到参考音时长 | 语速对齐 | 42% |
| DTW 逐帧压到参考音时长 | 节奏+时长全对齐 | **8%** |
| 保持原时长、只重排内部节奏 | 只对齐节奏结构 | 17% |
| 按参考音做逐频点 EQ | 音色对齐 | 75% / 58%（换参考音就回落） |
| 节奏 + 音色 | 最像参考音 | 8% |

**唯一"变好"的 EQ 组在交叉验证中站不住**：用 TTS 标准音做参考是 9/12，换成官方真人样本做参考就掉到 7/12，而基线两次都是 8/12 —— 平均值等于基线，是波动不是收益。

参考音本身是 TTS 合成（1.08 秒说完四个字），比真人自然语速快 40–55%。"向它对齐"等于把真人语音压成机器语速，方向就是反的。

## 二、实验设计

工具：`scripts/prosody_match.py`（配套 `scripts/prosody.sh`）

四件事在同一批句子上做完，模型和阈值完全不变，只变音频：

1. **切句**：`kws_test.split_speech` 按能量把 39.9 秒切成 12 句，逐句处理、逐句统计。
2. **节奏对齐**：40 维 log-mel（25ms 窗 / 10ms 步、逐句 CMVN）→ DTW（对角/水平/垂直三方向，欧氏距离）→ 得到双向映射。
   - `warp`：按「参考帧 → 源帧」把每句压成参考音的 1.08 秒（压缩比 ×0.50 ~ ×1.64）
   - `shape`：按「源帧 → 参考帧」× 尺度，把参考音的**音节相对比例**铺回源句总时长，总长不变
3. **音色对齐**：复用 `audio_bench.eq_curve_to_ref`，用参考音的长时平均语音谱做逐频点增益（限幅 ±18dB、5 点平滑），STFT 域施加。
4. **双模型判定**：
   - KWS：sherpa-onnx `kws-zipformer-wenetspeech-3.3M`，阈值 0.25 / 加分 1.0
   - ASR：`SenseVoice-small int8`，VAD 切句后整句识别，再做唤醒词模糊匹配

对照音频（28 秒，手机可直接听）：原声 9s → 节奏对齐 9s → 音色对齐 9s

## 三、结果明细

### 3.1 主实验（参考音 = TTS 标准音「你好兮兮」，1.08s）

```
组              KWS命中       SV唤醒
raw             0/12        8/12    你好西西 | - | 你好西西 | 你好嘻嘻
fast            0/12        5/12    你好谢谢 | - | 你好嘿呵 | 你好谢嘿
warp            0/12        1/12    你好西西 | - | 你看行行 | 你好谢谢
shape           0/12        2/12    你好谢嘻 | 我 | 你好谢 | 你好谢谢
eq              0/12        9/12    你好西西 | 好 | 你好欣星 | 你好嘻嘻
shape+eq        0/12        1/12    你好西嘻 | Oh | - | 你好谢谢
```

### 3.2 交叉验证（参考音 = 官方真人样本）

```
raw   8/12    fast 0/12    warp 1/12    shape 0/12    eq 7/12    shape+eq 0/12
```

基线两次完全一致（8/12），说明切句和判定链路稳定；`eq` 从 9 掉到 7，确认无真实增益。
节奏类处理两次都崩，确认有害是稳定的。

### 3.3 时间规整的实际强度

12 句里 11 句比参考音长，压缩比分布：

```
源时长   压到参考      保时长重排
1.30s → 1.08s ×0.83     1.30s ×1.00
2.18s → 1.08s ×0.50     2.19s ×1.00   ← 压掉一半
2.18s → 1.08s ×0.50     2.19s ×1.00
1.72s → 1.08s ×0.63     1.73s ×1.00
```

×0.50 意味着每个音素的时长被砍半，塞音和擦音的瞬态直接被吃掉 —— 这不是"更标准"，是**信息损毁**。

## 四、为什么方向是反的

1. **参考音是 TTS，不是"标准真人"。** SAPI 合成的「你好兮兮」是 1.08 秒匀速吐字；真人带停顿、拖音、重音，1.5–2.2 秒才是自然值。把真人往 TTS 上拉，等于学一个模型从没在训练集里见过的节奏。
2. **声学模型吃的是多样性，不是"标准"。** KWS/ASR 的训练数据里真人语速分布很宽，模型对自然语速鲁棒；对**局部变速**（DTW 的 ×2 / ×0.5 摆动）反而不鲁棒，因为变速会改变音素时长比例，破坏 fbank 特征的时序模式。
3. **EQ 只能改谱包络，改不了发音。** 音色对齐最多把频响拉近，但识别失败的主因在音素层面（见第五节），频谱整形碰不到。
4. **重采样实现细节也会引入失真。** `warp` 用整数索引抽样，压缩时直接丢样本，×0.50 相当于无抗混叠的抽取 —— 这一项本身就会制造噪声，所以 `warp` 的 8% 有一部分是加工副作用。但 `shape`（时长不变、抽样率 ≈1）同样是 17%，说明**即使排除重采样失真，节奏重排仍然有害**。

## 五、真正的瓶颈（此前已定位）

拆词验证是决定性的：

| 关键词 | KWS 命中 |
|---|---|
| `n ǐ h ǎo`（你好） | **10 次** |
| `x ī x ī`（兮兮） | **0 次** |
| `n ǐ h ǎo x ī` | 1 次 |
| `h ǎo x ī x ī` | 0 次 |

「你好」这一节模型是认识的，**卡在「兮兮」**。3.3M 参数的 KWS 模型对这个音节的建模几乎为零 —— 真人怎么念都不中，而 TTS 合成的同一句话 4/4 全中（因为 TTS 的音素时长规整，恰好落在模型稀疏覆盖的点上）。

所以：
- 不是麦克风问题（用户录音 1–4kHz SNR 38.1dB，比官方样本的 28.7dB 更干净）
- 不是发音问题（SenseVoice 12 句里 8 句听出「你好西西/嘻嘻」）
- 不是音频加工问题（本文档四组实验 + 之前的 11 种预处理全部无效）
- **是模型容量 + 唤醒词选词问题**

## 六、下一步（按性价比排序）

1. **换唤醒词**（最快、零成本）。工业界常规做法：唤醒词要选模型覆盖好的音节。「兮兮」是生僻拟声，换成「你好小智」「小智小智」「嗨小智」这类常见词，3.3M 模型大概率能稳定检出。
   验证方法：录一段包含 4 个候选词各 5 遍的音频，用同一套 KWS 跑对比表 —— 需要本人配合录音，**这是唯一能确证"换词有效"的实验**。
2. **用 SenseVoice 做唤醒**（已可用，当前 67%）。`scripts/wake_sv.py` 已跑通，RTF 0.018。代价是内存 239MB，上板需要算力评估。
3. **换更大的 KWS/ASR 模型**（sherpa-onnx 中文 KWS 只有一个 3.3M 模型，没有更大的可选；替代是流式 ASR + 关键词检索，等同第 2 条的重型版）。
4. **自训唤醒词模型**（成本最高，只在产品化阶段考虑）。

## 八、踩到的坑（供后续复用）

1. **`split_speech` 在 numpy int16 上溢出**：`v*v` 用 numpy int16 相乘会溢出成负数，`math.sqrt` 报 `math domain error`。已改成先 `float(v)`。用 `array('h')` 传入时不触发，用 `np.asarray(..., int16)` 传入时必崩。
2. **DTW 反查表会截断句首句尾**：用「参考帧 → 源帧」反查来生成"保时长"版本，只能覆盖 `m` 的值域，首尾整段丢失（第一版 `shape` 组掉到 17% 有这个成分）。正确做法是正向映射 `smap`（源帧 → 参考帧）再乘尺度。修完仍是 17%，才确认是真实现象。
3. **参考音必须是 16k 单声道 wav**：`kws_test.read_wav_mono16k` 只吃这个格式，mp3 要先过 ffmpeg。
