# 跨平台说明（Windows / Linux / 嵌入式真机）

> 目标：**一份 UI 代码，三个平台跑**。换平台只改 HAL 层，`src/ui/` 与 `src/main.c` 一行不动。

---

## 1. 分层：平台相关性只允许出现在 hal/

```
src/
├── ui/                 ← 【平台无关】纯 LVGL：样式、界面、事件、动画、定时器
│   ├── ui_theme.c/.h       样式表 + 明暗主题（只 include lvgl.h）
│   └── ui_indoor.c/.h      室内机主界面
├── hal/                ← 【平台相关】唯一的差异出口
│   ├── hal.h               统一接口：lv_display_t *hal_init(w, h)
│   ├── hal_sdl.c           Windows + Linux 桌面（SDL2）
│   └── hal_fbdev.c         Linux 真机（/dev/fb0 + evdev）—— P1 待实现
└── main.c              ← 【平台无关】lv_init → hal_init → ui_init → 心跳循环
```

**判断标准**：`src/ui/` 里如果出现 `#include <windows.h>`、`usleep`、`open("/dev/fb0")` 之类，就是分层破了。UI 层只允许 `lv_*`、标准 C（`time.h`、`stdio.h`）。

## 2. 三种后端对照

| | Windows（SDL） | Linux 桌面（SDL） | Linux 真机（fbdev） |
|---|---|---|---|
| 显示 | `lv_sdl_window_create` | 同左 | `/dev/fb0` mmap + 自写 `flush_cb` |
| 输入 | `lv_sdl_mouse_create` | 同左 | `/dev/input/eventX`（evdev）自写 `read_cb` |
| 依赖 | SDL2 | SDL2 | 无（内核自带 fbdev/evdev） |
| 构建 | `-DLVGL_HAL=sdl` | `-DLVGL_HAL=sdl` | `-DLVGL_HAL=fbdev` |
| 用途 | 日常开发 | 验证 Linux 编译/行为 | 上板联调 |
| 状态 | ✅ 已验证 | 待验证（需 WSL/VM） | ⬜ P1 |

## 3. 各平台构建

### 3.1 Windows（本机已验证）

```bash
# 依赖（MSYS2 MINGW64 里执行一次）
pacman -S --needed mingw-w64-x86_64-gcc mingw-w64-x86_64-cmake \
                   mingw-w64-x86_64-ninja mingw-w64-x86_64-SDL2
# 构建
mkdir -p build && cd build
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release ..      # 默认 LVGL_HAL=sdl
ninja && cd ../bin && ./main.exe
```

### 3.2 Linux 桌面（WSL2 / Ubuntu，代码零改动）

```bash
sudo apt install build-essential cmake ninja-build libsdl2-dev
cd lv_port_pc_vscode
git submodule update --init --recursive lvgl        # 首次
mkdir -p build && cd build
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release ..
ninja && cd ../bin && ./main
```

> WSL2 注意：Windows 11 自带 WSLg 可直接弹窗；Windows 10 需要额外 X server（VcXsrv）或改用真机/虚拟机。

### 3.3 Linux 真机（RK3308，交叉编译）

```bash
# 假设工具链：arm-linux-gnueabihf-gcc（Rockchip SDK 一般自带）
cmake -G Ninja -DCMAKE_BUILD_TYPE=Release \
      -DLVGL_HAL=fbdev \
      -DCMAKE_C_COMPILER=arm-linux-gnueabihf-gcc \
      -DCMAKE_CXX_COMPILER=arm-linux-gnueabihf-g++ \
      -DCMAKE_FIND_ROOT_PATH=/path/to/sysroot \
      ..
ninja
# 产物 scp 到板子 /root/ 下运行
```

## 4. fbdev HAL 要写的三件事（P1 作业书）

### 4.1 显示：flush_cb 把 LVGL 画好的块 memcpy 到 fb

```c
static int fb_fd;
static uint8_t *fb_mem;
static struct fb_var_screeninfo vinfo;
static struct fb_fix_screeninfo finfo;

static void fb_flush(lv_display_t *disp, const lv_area_t *area, uint8_t *px_map)
{
    /* ★ 逐行拷贝：源缓冲是"紧排"的，fb 有 line_length（stride）填充，不能一次 memcpy 整块 */
    uint32_t w = lv_area_get_width(area);
    uint32_t h = lv_area_get_height(area);
    uint32_t bytes_per_px = lv_draw_buf_get_bytes_per_pixel(...);  /* RGB565 = 2 */

    for (uint32_t y = 0; y < h; y++) {
        uint8_t *dst = fb_mem
                     + (area->y1 + y) * finfo.line_length
                     + area->x1 * bytes_per_px;
        memcpy(dst, px_map + y * w * bytes_per_px, w * bytes_per_px);
    }
    /* 若屏是 32bpp 而 LVGL 配 RGB565，需要在这里做 565→888 转换（或干脆 LV_COLOR_DEPTH=32） */
    lv_display_flush_ready(disp);       /* ★ 忘了这句 = 只刷一帧 */
}
```

### 4.2 输入：evdev read_cb

```c
static void evdev_read(lv_indev_t *indev, lv_indev_data_t *data)
{
    struct input_event ev;
    while (read(ts_fd, &ev, sizeof(ev)) == sizeof(ev)) {
        if (ev.type == EV_ABS) {
            if (ev.code == ABS_X) data->point.x = ev.value * SCREEN_W / TOUCH_MAX_X;
            if (ev.code == ABS_Y) data->point.y = ev.value * SCREEN_H / TOUCH_MAX_Y;
        } else if (ev.type == EV_KEY && ev.code == BTN_TOUCH) {
            data->state = ev.value ? LV_INDEV_STATE_PRESSED : LV_INDEV_STATE_RELEASED;
        }
    }
}
```

### 4.3 tick：LVGL 需要毫秒时基

```c
lv_tick_set_cb(my_tick_get_cb);   /* 内部 clock_gettime(CLOCK_MONOTONIC) 即可 */
```

### 4.4 真机上的三个约束（RK3308 特有）

1. **无 GPU**：纯软件渲染，`LV_COLOR_DEPTH` 用 16（RGB565）省一半带宽；
2. **内存 256MB 级**：`LV_MEM_SIZE` 从 128K 起试，`draw buffer` 用 1/10 屏（320×480 → 320×48×2B ≈ 30KB，双缓冲 60KB）；
3. **fb 可能不支持局部刷**：部分 BSP 的 fb 驱动整屏刷新慢，必要时用 `LV_DISPLAY_RENDER_MODE_PARTIAL` + 脏矩形，或评估 RGA（2D 加速）是否可用。

## 5. 版本差异（重要，别在面试里说错）

本仓库 lvgl 子模块是 **v10.0.0**（`lvgl/lv_version.h` 可查）。而**深渡存量项目大概率是 v8.3 或 v9.x**。

| 概念 | v8.3 | v9 / v10 |
|---|---|---|
| 当前屏幕 | `lv_scr_act()` | `lv_screen_active()` |
| 显示驱动 | `lv_disp_drv_t` + `lv_disp_drv_register` | `lv_display_t` + `lv_display_create` |
| 绘制缓冲 | `lv_disp_draw_buf_t` | `lv_draw_buf_t`（`lv_display_set_buffers`） |
| 按钮 | `lv_btn_create` | `lv_button_create` |
| 图片 | `lv_img_create` / `lv_img_set_src` | `lv_image_create` / `lv_image_set_src` |
| 缓存 | `lv_img_cache` | `lv_image_cache` |
| 事件目标 | `lv_event_get_target()` | `lv_event_get_target_obj()` |

**面试口径**：*"我用 v10 跑的模拟器，v8/v9 的 API 差异我清楚（屏对象、draw buf、img→image 这几个改名），v8 项目我能直接接。"*
