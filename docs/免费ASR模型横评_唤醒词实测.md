# 免费中文 ASR 模型横评（唤醒词场景）

> 目的：3.3M 的 KWS 模型对「你好兮兮」「你好小智」都无解（`你好` 能中、`兮兮`/`小智` 0 中），
> 换词也没救。那到底有没有**免费、体积可接受、准确率更好**的模型能用？
> 本文把 sherpa-onnx 生态里能直接跑的中文模型全捞出来，用同一批音频、同一把尺子量一遍。
>
> 测试日期：2026-10-28　环境：Windows + Python 3.11 + sherpa-onnx 2.0.1（CPU，4 线程）

---

## 一、结论先看

| 模型 | 体积 | 加载 | 「小智」逐段 | 「小智」整条 | 「兮兮」逐段 | RTF | 一句话 |
|---|---|---|---|---|---|---|---|
| **Qwen3-ASR 0.6B** | 937MB | 4.02s | **4/4** | 近1/1 | 近 **10/12** | 0.35 | 准确率天花板，但太重 |
| **Moonshine-base-zh** | **135MB** | **0.79s** | 3/4 | 1/1 全对 | 近 3/12 | 0.033 | 小体积最强，认字最准 |
| SenseVoice-small | 228MB | 1.77s | 2/4 | 1/1 全对 | 近 9/12 | 0.036 | 最均衡，短句最抗噪 |
| Dolphin-base | 99MB | **0.37s** | 2/4 | 1/1 全对 | 近 1/12 | **0.018** | 最快最省，短音频会漏字 |
| Zipformer-CTC-small | **60MB** | 3.46s | 1/4 | 1/1 全对 | 近 7/12 | 0.022 | 体积最小，长上下文会退化 |
| Paraformer-zh | 228MB | 2.57s | 0/4 | 近1/1 | 近 4/12 | 0.024 | 逐句最差，整条最强 |

（逐段 = 每句独立识别；整条 = 5.3 秒连说 4 遍一次性识别。近 = 近音字也算命中。）

四句话概括：

1. **有更好的模型，而且有的比现在用的更小。** `Moonshine-base-zh` 只有 135MB，
   把 4 段手机录音中的 3 段直接识别成「你好，小智」（现在用的 SenseVoice 是 2/4，且都是「小志」）。
2. **Qwen3-ASR 是准确率上限**：A 组严格 4/4、C 组 10/12，两项都是全场第一。
   代价是 937MB + RTF 0.35，PC 上能用，上板不用想。
3. **「体积大」不等于「更准」。** 228MB 的 Paraformer 在逐句场景里是所有模型里最差的（0/4）。
4. **上下文长度的影响比换模型还大。** 同一批音频，切单句和整条识别，准确率能差 3 倍
   （Paraformer：单句 3/12 → 整条 10/12）。详见 §六。

## 三、测试方法

### 3.1 三组音频（都是真人录音，不是合成音）

| 组 | 内容 | 条数 | 特点 |
|---|---|---|---|
| A | 手机录音「你好小智」，逐段 | 4 | 1kHz 以上被录音 App 砍掉，**最难的场景** |
| B | 同一段录音整条不切 | 1 | 5.3 秒连说 4 遍，测长上下文 |
| C | Jabra 麦克风录音「你好兮兮」，按能量切句 | 12 | 音质好但**词生僻**，测语言模型兜底能力 |

A 组的 4 段是用 SenseVoice 的 token 时间戳从连说录音里精确切出来的（见 §九 坑 9.1）。

### 3.2 两把尺子

- **严格**：识别文本里必须真的出现目标词（「小智」/「兮兮」）。
- **近似**：声母韵母都近的字也算中（智/志/知/治/制/质/资…，兮/西/嘻/熙/希/溪…）。

为什么两把都要：**所有模型都稳定地把「小智」听成「小志」**——用户说的是 zhì 音，
模型输出「志」在声学上完全正确。只看严格会误判所有模型都不行，
只看近似又会掩盖真实差距。两列并排才看得清。

### 3.3 RTF

`RTF = 推理耗时 / 音频时长`。0.02 意味着 1 秒音频用 20ms 算完（50 倍实时）。
实时唤醒要留余量，**RTF < 0.1 算安全**，除 Qwen3（0.35）外全部满足。

### 4.1 A 组：手机录音「你好小智」（逐段，最难）

```

               p02 你好，小智。         ★
               p03 是，你好，小智。     ★
               p04 人，那叫小智。       ★

Moonshine-zh   p01 你好，小智。         ★  严格 3/4
               p02 你好，小智。         ★
               p03 呃，你好，小智。     ★
               p04 人 力 他 想 治       ✗ 完全跑偏

SenseVoice     p01 你好，小智。         ★  严格 2/4
               p02 你好，小智。         ★
               p03 你好，小志。         ★近音
               p04 那要小志。           ★近音

Dolphin        p01 你好小智。           ★  严格 2/4
               p02 （空）               ✗ 漏识别
               p03 小                   ✗ 只出一个字
               p04 你好你好小智。       ★

Zipformer-CTC  p01 你好小志             ★近音 严格 1/4
               p02 你好小吃             ✗
               p03 你好想吃             ✗
               p04 那叫小智             ★

Paraformer     p01 你好小志             ★近音 严格 0/4
               p02 是你好小志           ★近音
               p03 你好小吃             ✗
               p04 人那下小志           ★近音
```

**看点**：只有 Qwen3 能做到 4 条全对。Moonshine 是"小体积组"里唯一能把「小智」写成
「小智」（而不是「小志」）的，说明它的中文语言模型对「小智」有正确先验。
Dolphin 也能写对字，但会漏识别（p02 输出空）。

### 4.2 B 组：整条 5.3 秒连说 4 遍

```
Qwen3         你好，小志。你好，小志。你好，小志。你好，小志。
Moonshine     你 好 小 智 你 好 小 智 你 好 小 智 你 好 小 智
Dolphin       你好小智 你好小智 你好小智 你好小智
Zipformer-CTC 你好小智你好小智你好小智你好小智
SenseVoice    你好，小智你好，小智你好，小智你好，小智。
Paraformer    你好小志你好小志你好小志你好小志
```

除 Paraformer（严格 0，全是「小志」）外全部 4 遍全对。

**这一组说明：只要上下文够长，所有模型都能把这四个字认出来。问题从来不在"认不出"。**

### 4.3 C 组：Jabra「你好兮兮」12 句（逐段）

| 模型 | 近似命中 | 典型输出 |
|---|---|---|
| **Qwen3** | **10/12** | 你好，西西 / 你好，嘻嘻 |
| SenseVoice | 9/12 | 你好，西西 / 你好，嘻嘻 / 你好，西欣 |
| Zipformer-CTC | 7/12 | 你好西西 / 你好谢西 / 你好西 |
| Paraformer | 4/12 | 你好西嘻 / 你好谢谢 / 你好嘻嘻 |
| Moonshine-zh | 3/12 | 你好，嘻嘻 / 你好，西西 / 还幻觉出「我們來看看」 |
| Dolphin | 1/12 | 你好试试 / 你好先生 / 你好电视 |

「兮兮」是生僻拟声词，模型的**语言模型先验**会把它强行掰到高频词上——
「谢谢」「试试」「先生」「亲亲」「星星」。这不是声学问题，是语言模型问题。

注意 Qwen3 和 SenseVoice 输出的是**带标点的规范句**（「你好，西西。」），
而 Moonshine 输出带空格（「你 好 小 智」），预处理时都要清理。

### 4.4 同一批音频整条识别（40 秒）

| 模型 | 「兮兮类」命中 | 备注 |
|---|---|---|
| **Paraformer** | **10/10** | 全篇一致「你好西西」 |
| SenseVoice | 6/10 | 「西嘻」「西西」混杂 |
| Moonshine-zh | 未测 | — |
| Dolphin | 0/10 | 你好试试 你好先生 你好电视 |
| Zipformer-CTC | 0/10 | 你好你好你好你好谢西你好 |
| Qwen3 | **不可用** | 超过 512 token 上限，直接被截断，输出空 |

**Paraformer 从逐句 4/12 跳到整条 10/10**，是所有模型里跨度最大的。

**Qwen3 有个硬限制**：`max_total_len=512`，约 38 秒音频就到顶，
超了会打印 `context_len exceeds max_total_len` 并把音频占位符截掉，最终输出空串。
所以它只能处理短片段——对唤醒词（1~2 秒）够用，对整段转写不行。

## 五、六个模型的画像

**Qwen3-ASR 0.6B（937MB）** — 准确率天花板。
A 组唯一 4/4、C 组 10/12 全场第一，而且输出带标点、可直接读。
代价：937MB、加载 4 秒、RTF 0.35（1.7 秒音频要算 0.6 秒）。
**单次最多约 38 秒音频**，超了输出空。适合 PC 端做"最终裁判"或做训练数据标注，
**不适合上板**。

**Moonshine-base-zh（135MB）** — 小体积组最优。
中文微调扎实，「小智」能写对；加载 0.79 秒；输出带空格要清理。
弱点：生僻词会**幻觉**（s01 输出了完全无关的一整句「你 好 詩 詩 我 們 來 看 一」），
实际使用必须配"限定关键词 + 只取前 2 秒"的约束，不能让它自由发挥。

**SenseVoice-small（228MB）** — 最均衡。
逐句抗噪最好之一（C 组 9/12），短音频不塌。但对「小智」总输出「小志」，
整条识别时反而掉到 9/12，上下文利用能力有限。**实时逐句场景的稳妥选择**。

**Dolphin-base（99MB）** — 最快最省。
RTF 0.018、加载 0.37 秒、99MB，是上板第一候选。对「小智」写对字。
致命弱点：**短音频会漏识别**（p02 输出空、p03 只出一个「小」），
语言模型先验极强，遇到「兮兮」直接判成「先生」「电视」。
用在**已知固定唤醒词**场景没问题，开放词汇会翻车。

**Zipformer-CTC-small（60MB）** — 体积最小。
60MB 能跑到 C 组 7/12，性价比不错。但**上下文越长越差**
（单句 4/12 → 整条 1/12），只适合"切小段立即识别"，不能攒长语音。
加载最慢（3.46s），启动体验差。

**Paraformer-zh（228MB）** — 极端的双面。
逐句垫底（A 组 0/4、C 组 4/12），但整条识别 10/10 全对、全篇一致。
高度依赖语言模型的上下文一致性，**最不适合逐句实时，最适合整段转写**。

## 六、关键发现：上下文长度是隐形变量

把 C 组 12 句按不同颗粒度拼起来喂，看准确率怎么变化：

| 每次喂几句 | Paraformer | SenseVoice | Dolphin | Zipformer-CTC |
|---|---|---|---|---|
| 1 句（约 2s） | 3/12 | 7/12 | 0/12 | 4/12 |
| 2 句（约 4s） | 5/12 | **10/12** | 0/12 | 4/12 |
| 3 句（约 6s） | 7/12 | 10/12 | 0/12 | 3/12 |
| 4 句（约 9s） | 8/12 | 10/12 | 0/12 | 1/12 |
| 6 句（约 13s） | 8/12 | 10/12 | 0/12 | 1/12 |
| 12 句（约 40s） | **10/12** | 9/12 | 0/12 | 1/12 |

四条曲线，四种形状：

- **Paraformer 单调上升**：靠上下文堆语言模型先验，越长越准。
- **SenseVoice 两句话就饱和**：2 句到 10/12，之后不再涨，整条反而略降。
- **Dolphin 全程 0**：不是上下文问题，它就不认这个词。
- **Zipformer-CTC 越长越崩**：长上下文会污染它。

**工程含义**：实时唤醒不要把音频切得太碎。
现有 `wake_sv.py` 是"一句一识别"，按这张表，改成
**"带前 1~2 秒上下文再识别"**，SenseVoice 就能从 7/12 提到 10/12。
这个改动比换模型收益更大，而且不增加任何体积。

## 七、选型建议

| 场景 | 推荐 | 理由 |
|---|---|---|
| 准确率优先（PC 端、离线标注、最终裁判） | **Qwen3-ASR 0.6B** | 4/4 + 10/12 全场第一，代价 937MB |
| PC 端 demo / 唤醒词「你好小智」 | **Moonshine-base-zh** | 3/4，唯一把「小智」写对的小模型，135MB |
| 实时逐句、追求稳定不塌 | **SenseVoice-small** | 短句抗噪最好，配 2 句上下文可达 10/12 |
| 上板（内存 < 200MB、算力弱） | **Dolphin-base** | 99MB、RTF 0.018、加载 0.37s |
| 上板（体积极限） | **Zipformer-CTC-small** | 60MB，但要小段切、别攒长 |
| 整段录音转写（非实时） | **Paraformer-zh** | 整条 10/10，全篇一致 |
| 唤醒词是生僻词（兮兮这类） | **Qwen3 或 Paraformer + 长上下文** | 只有它们能靠上下文把生僻词拉回来 |

**共同前提**：无论选哪个，都必须在匹配层做**近音容错**。
所有模型都把「小智」听成「小志」、把「兮兮」听成「西西/嘻嘻/谢谢」，
不做容错等于白测。现有 `wake_sv.py` 的近音表已覆盖。

## 九、踩坑

**9.1 切句必须用 token 时间戳，不能用能量 VAD。**
手机录音里 4 遍「你好小智」连说无停顿，能量包络完全粘连，
`split_speech` 只会切出 1 段。正确做法是拿 SenseVoice 的 `result.timestamps`
找每遍首字「你」和末字「智」，中点作边界。

**9.2 hf-mirror 的 `resolve` 会被限流（429），`raw` 不会，但 `raw` 拿不到 LFS 大文件。**
- 大模型文件 → 必须 `resolve`（`raw` 只返回一行 `version https://git-lfs...` 指针）。
- 小文本（tokens.txt / bbpe.model）→ 走 `raw`。
- 注意：**有些小文件（如 Qwen3 的 vocab.json）本身也是 LFS 管理的**，
  用 `raw` 只会拿到 132 字节的指针，必须走 `resolve`。判断方法：看文件内容以
  `version https://git-lfs` 开头就是指针。

**9.3 sherpa-onnx 2.0.1 各构造器的参数名不统一，别猜。**
本轮踩到三个：
- `from_moonshine` 的参数是 `preprocessor`，不是 `preprocess`；
- `from_zipformer_ctc` **没有** `bpe_vocab` 参数，多传直接 `unexpected keyword`；
- 两文件版 Moonshine（`encoder_model.ort` + `decoder_model_merged.ort`）要走
  `from_moonshine_v2`，用老接口报 `Please provide a model`。

正确姿势：
```python
print(sherpa_onnx.OfflineRecognizer.from_xxx.__doc__)
```

**9.4 Qwen3-ASR 有 512 token 上限，长音频静默失败。**
超过约 38 秒音频会打印 `context_len (534) exceeds max_total_len (512)`
然后把音频占位符截掉，**最终输出空字符串**，不报异常。
如果只看结果不看 stderr，会以为模型"不认字"。控制单段长度 ≤ 30 秒。

**9.5 别用合成音测"哪个词更好"。**
上一轮已验证：SAPI 合成的「你好兮兮」和「你好小智」在 KWS 上表现完全一致，
但真人说「兮兮」0/12。**合成音没有区分度**，必须真人录音。

**9.6 严格命中率会被"同音字"骗。**
「小智」→「小志」是模型正确的声学判断，不是错误。
只报严格命中会把 Moonshine（3/4）和 Paraformer（0/4）的差距放大到失真。
两把尺子并排看才准。
