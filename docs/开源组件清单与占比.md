# 开源组件清单与代码占比

> 统计脚本：`scripts/stat_lines.py`（源码行数）、`scripts/stat_binary.py`（产物字节，
> 直接读 COFF 段头，不依赖 cloc）。数据取自当前工作区，可随时复跑复核。

---

## 0 结论先摆出来

| 口径 | 开源 | 自研 | 自研占比 |
|---|---|---|---|
| **A 仓库源码总量**（物理行） | 616,687 行 | 17,718 行 | **2.8%** |
| **B 实际编入产品的 LVGL** | 98,122 行 | —— | 上游 58 万行，只用了 **17%** |
| **C 目标文件体积** | 1,296,888 字节 | 126,000 字节 | **8.9%** |

一句话：**这是一个 90% 靠成熟库、10% 靠选型和集成的项目**。代码行数本来就不该是
这类项目的价值指标，真正的工作量在：

- **挑对库**：LVGL 而不是 Qt（体积差一个数量级）；oSIP 而不是 pjsip（许可）
- **裁到能跑**：LVGL 58 万行 → 实际编入 9.8 万行；固件 2.79 MB → **1.82 MB**（-35%）
- **接起来**：SIP 状态机、G.711、媒体线程划分、OEM 白牌层
- **把坑变成资产**：README 里 20 多条踩坑记录，每条都对应一个现场故障

## 1 三个统计口径，分别说明

单一百分比最容易骗人，所以三个都列。**被问到先报口径，再报数字。**

### 口径 A：仓库源码总量

把仓库里参与构建的源码全算上（LVGL 整包 + libosip2 + 自研），
**不管这些代码最终有没有被编译进去**。

| 组件 | 文件数 | 行数（物理行） | 许可 |
|---|---:|---:|---|
| **LVGL 10.0.0** `lvgl/src` 全量 | 930 | **583,538** | MIT |
| ├ 其中 `src/font`（字体位图数组） | 44 | 196,882 | MIT / OFL |
| ├ 其中 `src/libs`（thorvg 等内嵌库） | 227 | 152,196 | MIT 等 |
| │ 　└ 其中 ThorVG 0.15.3 | 137 | 59,191 | MIT |
| └ 其余（core/draw/widgets/misc/…） | 659 | 234,460 | MIT |
| **libosip2 5.3.2** | 104 | **33,149** | **LGPL-2.1** |
| 自研 `src/` | 42 | 16,108 | 私有 |
| ├ 其中 `ui_font_cjk_{16,24}.c`（脚本生成） | 2 | 8,973 | 私有 |
| └ 其中手写逻辑 | 40 | 7,135 | 私有 |
| 自研 `tools/`（sip_echo、h264_probe） | 2 | 639 | 私有 |
| `scripts/`（dev.sh、gen_font.py、统计脚本） | 7 | 971 | 私有 |
| **合计** | **1,085** | **634,405** | |

- 开源小计 **616,687 行 = 97.2%**
- 自研小计 **17,718 行 = 2.8%**（去掉脚本生成的字库，手写只有 8,745 行）

> 这个口径的坑：LVGL 里 83% 的代码根本没编进去。拿 583K 当"我的代码量"是虚的，
> 拿 2.8% 又显得没干活 —— 所以要口径 B。

### 口径 B：实际编入产品

LVGL 靠 `lv_conf.h` 的宏做条件编译，关掉的模块**整个文件编成空目标文件**。
用产物里 `.text` 段是否为 0 判定"这个文件到底有没有代码进来"：

```bash
python scripts/stat_binary.py     # 读 .obj 的 COFF 段头，按模块汇总
```

| 项 | 上游总量 | 实际编入 | 比例 |
|---|---:|---:|---:|
| LVGL（有代码的目标文件） | 583,538 行 / 930 文件 | **98,122 行 / 170 文件** | **16.8%** |
| libosip2 | 33,149 行 | 33,149 行（几乎全用） | 100% |
| 自研 | 16,108 行 | 16,108 行 | 100% |

**"上游 58 万行，我只用了 9.8 万行"** —— 这句话比任何百分比都更能说明在"裁剪"。

关掉的典型：19 个 Montserrat 字号只留 3 个、ThorVG 矢量引擎、lodepng/JPEG/BMP/TTF
解码器、二维码、Wayland/X11/各种 MIPI 屏驱动、ARM2D/NEON/SVE 加速分支、
单元测试与 profiler，以及 `lvgl_examples` / `lvgl_demos` 两个整包。

### 口径 C：目标文件体积

按编译单元累加 `.text` + `.rdata` + 已初始化 `.data`（不含 `.bss`）：

| 组成 | 字节 | 占比 |
|---|---:|---:|
| **LVGL**（含软件渲染、字体、控件） | 1,219,888 | **85.7%** |
| **自研** | 126,000 | **8.9%** |
| **libosip2**（静态库内目标文件） | 77,280 | 5.4% |
| 合计 | 1,423,168 | 100% |

`bin/main.exe` 实测 **1,907,214 字节（1.82 MB）**。差值（约 480 KB）是 gcc 链接
保留的符号表与 PE 段对齐 —— 上板后 `strip` 一下就没这一块。

自研 126 KB 拆开看：

| 模块 | 字节 | 说明 |
|---|---:|---|
| `src/ui` | 85,040 | 其中 **70,288 是中文字库位图**（212 字 × 16/24px） |
| `src/app` | 36,960 | SIP 状态机 + G.711 + 设备模型 + 事件总线 |
| `src/oem` | 6,368 | 两套客户配色/文案 |
| 其他 | 1,632 | main / hal / 鼠标光标 |

> 注意：**自研体积里 56% 是字体位图**，不是逻辑代码。真写出来的 C 逻辑约 50 KB。

## 2 逐个组件：它是谁、干什么、能不能换

| 组件 | 版本 | 许可 | 在本项目的作用 | 链接方式 | 现状 |
|---|---|---|---|---|---|
| **LVGL** | 10.0.0 | MIT | GUI：控件、布局、字体、软件渲染 | 静态（子模块） | 在用。换 Qt 体积 20MB+ 且要 GPU |
| **ThorVG** | 0.15.3 | MIT | SVG / 矢量渲染 | 静态（LVGL 内嵌） | **已关闭**（项目无矢量需求） |
| **lodepng** | 内嵌 LVGL | zlib | PNG 解码 | 静态 | **已关闭**（图标用 `LV_SYMBOL_*`） |
| **TJPGD** | 内嵌 LVGL | BSD 系 | JPEG 解码 | 静态 | **已关闭**（将来接视频另走 H.264） |
| **BMP** | 内嵌 LVGL | MIT | BMP 解码 | 静态 | **已关闭** |
| **TinyTTF** | 内嵌 LVGL | MIT | TTF 运行时渲染 | 静态 | **已关闭**（用预生成子集字库） |
| **QRCODE** (qrcodegen) | 内嵌 LVGL | MIT | 二维码显示 | 静态 | **已关闭**（做扫码配网时再打开） |
| **libosip2** | 5.3.2 | **LGPL-2.1** | SIP 报文编解码（REGISTER/INVITE/SDP） | **静态** | 在用。同族 eXosip 同为 LGPL |
| **SDL2** | 2.32.10 | zlib | PC 模拟的显示 + 输入 + 音频 | **动态**（`SDL2.dll` 2.4 MB，**仅 PC**） | 板子换 fbdev + evdev + ALSA |
| **zlib** | 1.3 | zlib | SDL2 依赖 | 动态 | 仅 PC |
| **FreeRTOS** | —— | MIT | 预留的 RTOS 形态 | **未使用**（submodule 为空） | 备选路线 |
| **FFmpeg** | 9.0.2 | LGPL/GPL（视编译选项） | **仅 `tools/h264_probe` 用** | **独立工具进程，不进产品** | 产品将来只链 `libavcodec` |

### 必须单独说清的两件事

**① FFmpeg 不在产品里（现在）。**
`h264_probe` 是个独立小工具，用来量"解码一帧要多久"。产品将来只链接
`libavcodec`（不是 `libavformat`，也不需要 `ffplay`）。交叉编译加
`--disable-programs --disable-avformat --disable-protocols` 后，FFmpeg 从 60MB 裁到 1.5MB。

**② SDL2 只在 PC 上存在。**
板子上是 `hal_fbdev.c` + evdev + ALSA，`SDL2.dll` 那 2.4 MB 不会出现在设备里。
这正是把 HAL 抽出来的原因 —— PC 调 UI，板子跑同一套上层代码。

## 3 LGPL-2.1：libosip2 是这份清单里唯一"有义务"的组件

其他库（MIT / zlib / BSD）只要保留版权声明。**libosip2 是 LGPL-2.1，静态链接
属于衍生作品**，义务三条：

| 义务 | 具体做法 | 现状 |
|---|---|---|
| 提供库的完整源码 | 附上游 tarball 或可访问的下载地址 | `third_party/libosip2-5.3.2.tar.gz` 已在仓库 |
| 允许替换库并重新链接 | 提供 `.o`/`.a`，或改动态链接 | **待办**：交付包附 `.a` + 链接说明 |
| 声明使用了它 | 固件里放 `NOTICE` / 关于页 | **待办** |

三条落地建议（成本从低到高）：

1. **交付包附 `LICENSES/`**，放 libosip2 的 COPYING 和我们的修改说明（目前零修改）。
2. **附 `.a` 与构建说明**，让客户能换库重新链接 —— 这一步就满足 LGPL 的核心要求。
3. **改动态链接 `libosip2.so`**，义务最轻，代价是板子上多两个 `.so`（约 340 KB）。

> 面试里这条很加分："选型时查过许可。MIT/zlib 随便用；LGPL 静态链接要提供
> relink 能力；GPL 的一律不能用 —— 所以我们没选 pjsip。"

## 4 实测：一次裁剪把固件从 2.79 MB 压到 1.82 MB

`lv_conf.h` 的默认模板几乎把所有可选件都开着。这轮按产品实际需求裁了一遍，
**每一步都验证过编译与通话不回归**（注册 + INVITE + RTP 50pps + 内存 3%）。

| 项 | 裁前 | 裁后 | 省下 |
|---|---:|---:|---:|
| 19 个 Montserrat 字号 + DejaVu + UnscII | 1,037,776 | 137,808 | **900 KB** |
| ThorVG 矢量引擎（含 `LV_USE_VECTOR_GRAPHIC`） | 487,552 | 0 | **488 KB** |
| lodepng / TJPGD / BMP / TinyTTF / QRCODE | 189,856 | 5,168 | **185 KB** |
| 示例与 demo 目标（`lvgl_examples`/`lvgl_demos`） | 编译但不链接 | 不编译 | 编译时间 3 min → 40 s |
| **目标文件合计** | 2,948,992 | 1,345,888 | **-54%** |
| **`bin/main.exe`** | 2,923,962（2.79 MB） | 1,907,214（**1.82 MB**） | **-35%** |

exe 只降 35% 而不是 54%，原因是**符号表是固定开销**：代码越少，它在文件里占比越大。
设备上 `strip` + `-Os` 之后看到的就是接近 54% 的收益。

### 裁剪过程踩到的两个真坑（都写进 README 了）

1. **关 `LV_USE_THORVG` 会直接编译失败**：`lv_draw_vector.c` 里有
   `#error "LV_USE_VECTOR_GRAPHIC requires ... LV_USE_THORVG ..."`。
   必须**同时**关 `LV_USE_VECTOR_GRAPHIC` —— LVGL 10 把矢量图形和 ThorVG 绑死了。
2. **`lvgl_demos` 硬引用 `lv_font_montserrat_20`**。裁字体后 demo 编译报
   `undeclared (first use in this function)`。正确做法不是"留下 20 号字体迁就 demo"，
   而是**根本别编 demo**：`CONFIG_LV_BUILD_DEMOS=OFF`。顺带把全量编译从 3 分钟
   降到 40 秒。

### 还能再压多少

| 项 | 可省 | 代价 |
|---|---:|---|
| 未用到的 widgets（chart/calendar/keyboard/menu/table/spinbox…） | ~120 KB | 要逐个确认未引用 |
| `LV_USE_FS_STDIO` + 字体管理器 | ~10 KB | —— |
| `strip` + `-Os` + `--gc-sections`（上板） | 未知，通常 15~25% | 不能在线调试 |
| 去掉调试用 `LV_USE_LOG` / `assert` | ~5 KB | 排查变难 |

## 5 复跑方式

```bash
python scripts/stat_lines.py             # 源码行数（自研 vs 上游）
python scripts/stat_binary.py            # 产物字节（按模块）
python scripts/stat_binary.py build-64k  # 指定别的构建目录
```

两个脚本只依赖 Python 标准库，Windows / MSYS2 / Linux 都能跑。

## 6 面试怎么讲（30 秒版）

> "这个固件 1.82 MB，我写的大概 9%，85% 是 LVGL，5% 是 oSIP。
> 但 LVGL 上游 58 万行我只用了 9.8 万行 —— 靠 `lv_conf.h` 裁掉了 83%。
>
> 原始模板编出来 2.79 MB，我把没用到的 16 个字号、ThorVG 矢量引擎、
> 几个图片解码器关掉，压到 1.82 MB，功能一个没少，通话回归通过。
> 中间踩了两个坑：LVGL 10 的矢量图形和 ThorVG 是绑死的，得一起关；
> lvgl_demos 硬引用 20 号字体，所以不能靠留字体迁就它，得直接不编 demo。
>
> oSIP 是 LGPL，静态链接要提供 relink 能力，交付时得附 `.a` 和许可声明 ——
> 这条我在选型时就查过了。"
